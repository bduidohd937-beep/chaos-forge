# PROJECT REFORGE · CHAOS FORGE V2.0 Alpha Phase 1

> 설계 검토용 브랜치 `feature/v2-reforge-phase1`. **main 배포에 반영하지 않는다.**
> UI는 코딩 완료 상태지만, 실제 데스크톱/모바일 브라우저 수동 검수는 아직 별도 진행이 필요하다.

## 채택된 제품 원칙

- **FREE:** 메인 장르 1개 + 서브 장르 0~3개, 모든 조합 허용.
- **BALANCED:** CHAOS는 게임처럼, FORGE는 글쓰기 스튜디오처럼.
- **MIX:** 전체 회전, 순차 확정, 즉시 모드 공존.
- **HYBRID:** 추첨은 간단한 키워드 중심, 기획 확장은 FORGE에서 진행.

## 4개의 업무 화면

1. **SETUP**: 생성기 4종, 메인·서브 장르, 장르 맞춤/하이브리드/완전 랜덤, 혼돈 수치.
2. **CHAOS**: 추첨(클래식/슬롯/즉시), 카드 잠금, 부분 재추첨, 결과 복사·JSON/MD 내보내기, 보관함 저장.
3. **FORGE**: 읽기용 조합 프리뷰와 원본 슬롯, 직접 편집하는 제목·메모(브라우저 자동 저장). 상세 플롯/스탯 편집기는 후속 단계.
4. **LIBRARY**: 기존 아이디어 불러오기/삭제/검색, 사용자 키워드 생성·삭제.

## 장르 엔진

- `src/data/genres.js`의 STORY 17개와 GAME 8개를 통합해 **25개 장르**를 노출.
- `src/genreMix.js`에 기존 서로 다른 태그를 연결하는 명시적 호환 테이블.
- 장르 맞춤 모드에서 메인 **0.55**, 서브 장르 합계 **0.45**를 초기 그룹 추첨 가중치로 적용.
- 특정 슬롯의 태그 풀이 비어 있다면 해당 슬롯에서 실제 존재하는 선택 장르 집합으로 재정규화. 모든 선택 장르가 비면 원본 풀을 사용.
- 혼돈 레벨은 1~5; 하이브리드는 선택 장르 밖 확률을 기존 공식으로 유지.
- 완전 랜덤은 장르 반영 없이 가중치만 사용.
- 폭주 추첨은 일회성으로 하이브리드 혼돈 5를 적용하되 기존 모드·슬라이더는 유지.
- 개별 재추첨은 대안이 있으면 직전 키워드와 같은 결과를 피하도록 설계.

**주의:** 현재의 게임 장르 태그와 스토리 장르 태그를 1:1로 의미적으로 해석하는 것은 불가능하므로, 호환 테이블은 근사치다. 출시 전에 장르별 슬롯 커버리지 분석과 키워드 데이터 증설이 필요하다.

## Alpha 3 · 생성 품질과 키워드 다양성 (실제 구현)

- **전체 조합 플래너 `src/composition.js`:** 결과 8~9칸을 각각 독립적으로 뽑는 대신, 메인 장르의 핵심 슬롯 하나를 먼저 확보하고(잠금에서 이미 반영된 경우 제외), 가능한 경우 서브 장르 최대 세 개를 서로 다른 슬롯에 배분한다. 스토리의 미스터리는 사건/반전, 로맨스는 갈등/인물, 코미디는 분위기 등 슬롯 역할에 따라 우선순위를 준다.
- **장르 맞춤 / 하이브리드 혼돈 1~3:** 대표 장르가 실제 태그에 존재하면 해당 슬롯은 그 장르에 맞는 키워드만 뽑도록 한다. 다만 불가능한 장르·잠금 조합까지 보장할 수는 없다.
- **하이브리드 혼돈 4~5:** 메인 장르의 한 슬롯만 고정하고 나머지는 높은 혼돈을 허용한다. 완전 랜덤은 장르 계획 자체를 적용하지 않는다.
- **가중치 추첨:** 단일 슬롯의 기존 메인 55%·서브 45% 설정을 유지하되, 최근 사용으로 한 장르의 선택지가 소진되면 다른 선택된 장르의 새 키워드를 우선한다.
- **수작업 보강 127개:** `src/data/alpha3.js`에 STORY 32개, GAME 32개, CHARACTER 27개, HERO 36개를 추가했다. GAME/HERO에도 로맨스·추리·코미디·판타지·SF 등 서사 장르 태그가 직접 붙은 표현을 보강했다. 기존 키워드는 삭제하지 않는다.
- **반복 방지:** 슬롯별 최근 최대 4개 결과를 새 초안 필드 `recentHistory`로 로컬 저장한다. 전체 생성과 개별 재추첨 모두 최근 값이 아닌 새 키워드를 우선한다. 장르에 맞는 후보가 정말 하나뿐일 때는 관련 없는 값을 뽑지 않고 재사용할 수 있다. 잠금 항목은 기록 갱신에서 제외한다.
- **검증:** `tests/alpha3.test.js`와 `tests/app.test.jsx`에서 다장르 구성·키워드 정합성·4개 생성기 커버리지·혼돈·잠금·다양성·새로고침 후 이력·기존 모드의 호환성을 검사한다. 자동 테스트 **105개 통과**, 빌드 성공 (2026-10-29 CI).
- **중요한 한계:** 장르 태그를 활용하는 제약·가중치 엔진이지 생성형 언어 모델이 아니다. 선택된 태그가 나타난다는 것은 문장 수준에서 개별 설정 간 인과관계나 서사적 자연스러움이 완벽하다는 뜻이 아니다. 불가능한 장르 조합을 결과에 억지로 넣지 않는다.

이 단계는 운영 V1.x가 아니라 **별도 /preview/v2/**에만 반영하는 대상으로 한다.

## Alpha 5 · CREATIVE DNA + KEYWORD REVOLUTION (독자 시스템)

### 도입 이유

기존 키워드는 종류와 개수가 늘어도 사용자마다 요구하는 **소재, 길이, 독창성, 분위기**가 다르다. 단순한 확률 조절이나 결과 다시 뽑기만으로는 사용자가 원하는 방식에 수렴하지 않으므로, 로컬 규칙 기반의 **선호·차단·변이 엔진**을 도입한다.

### 독창적인 UX/알고리즘

1. **CREATIVE DNA** (`src/creativeDNA.js`): 간결/기본/구체적, 독창성 1–4, 선호 분위기(균형/따뜻함/어두움/유쾌함), 사용자가 좋아요 누른 문구를 저장. 일부 선호는 절대 조건이 아닌 가중치로 반영한다.
2. **SPARK / ECHO / RIFT**: SPARK는 일반 추첨, ECHO는 기존 결과에서 의미 있는 *한 슬롯을 추첨 1회에만* 보존하고 나머지를 재추첨(지속 잠금 미변경), RIFT는 기존 소재와 다른 고독창성 소재를 우선한다. RIFT는 사용자가 설정한 기본 독창성/혼돈 값을 자동 변경하지 않는다.
3. **BAN MANAGER**: 카드의 `문구 제외`는 구체적 표현·짧은/상세 변형 전체를 **항상 엄격히 제거**. SETUP에서는 소재 10종, 표현 스타일 4종에 대해 완전 차단/출현 최소화를 선택할 수 있다. 기존 한국어 표현에는 공개된 동의어 목록(예: 좀비/언데드/되살아난 시체)을 적용하고, 새 키워드에는 명시적 소재 메타데이터를 부착한다.
4. **절대 차단 준수**: 설정된 차단은 장르 무작위 모드, 잠금 제외 재추첨, 추첨 슬롯 애니메이션까지 적용된다. 필터링으로 가능한 풀이 없어지면 **이전 결과를 조용히 삭제하거나 차단을 무시하지 않고 사용자에게 부족한 슬롯을 알려준다**. 기존에 잠금된 금지 문구는 사용자 소유의 작성 내용을 유지하며, 충돌 메시지로 알린다.
5. **키워드 도감·품질 점검**: 생성기별 키워드 수, 각 슬롯의 보유량, 중복 여부, 깊이별 변형 보유량을 읽기 전용으로 집계한다. 품질 점검을 위한 진단이지 '모든 표현의 의미가 자연스럽다'는 자동 보증은 아니다.

### 신규 콘텐츠 및 표현 방식

- `src/data/alpha5.js`: **68개 별도 창작 콘셉트**(STORY 16, GAME 16, CHARACTER 18, HERO 18). 모든 콘셉트에 직접 작성한 간결/기본/구체적 표현 **3종**과 장르·분위기·독창성·소재 태그를 제공한다.
- 기존 Alpha 3 키워드 127개 및 레거시 키워드는 지우거나 일괄 교체하지 않고 새 데이터 풀에 추가한다.
- **모든 기존 키워드에 상세 변형이 존재하는 것은 아니다.** 해당 항목은 원문을 유지하며, 상세 표현 제공 후보의 가중치를 올린다. 긴 문장을 단순히 뻥튀기한 것처럼 제시하지 않는다.

### 기존 기능/데이터와 호환

- 기존 로컬 초안 키 `chaosforge.reforge-preview.v2.draft`의 `creativeDNA` 하위 필드에 새 취향을 저장한다. 없거나 깨진 경우 적절한 기본값으로 복원한다. 기존 결과, 잠금, FORGE 작성 내용, 4회 단기 재추첨 기록은 유지한다.
- 사용자 취향은 계정 서버나 외부 서비스에 업로드하지 않는다. 이 기능은 **AI가 사용자를 학습하는 기능이 아니라 명시적 선호 데이터와 규칙/가중치를 적용하는 기능**이다.
- 저장 공간이 비활성화된 브라우저에서 자동 저장이 실패하면 오류 상태를 표시한다. 중요한 작업의 JSON 백업은 추후 LIBRARY 통합 백업 기능과 별개로 권장한다.

### 검증 및 남은 한계

- Vitest에서 68개 키워드의 3단계 표현/태그/중복을 확인하고, 주제 동의어, 완전 차단, 유연 차단, 특정 표현 제외, 변형 간 동일 문구 차단, 고정 결과·초안 보존, ECHO/RIFT, UI 설정·리로드 복원을 검증한다.
- 기존 스타일 규칙은 형태소 분석이 아닌 텍스트 패턴 기반이며 **은유나 미등록 동의어를 100% 이해하지 못한다**. 향후 사용자 의견을 기반으로 태그를 정교화해야 한다.
- 사용자 피드백을 통한 장기 반복 학습/추천 모델, 전체 소재 의미 분류, 문장 자동 생성은 이번 범위에 포함하지 않는다.
- 운영 V1.2.1은 여전히 배포 루트에 남기고 새 기능만 별도의 `/preview/v2/`에 반영한다. 실제 PC/모바일 디자인·조합 품질 수동 검수는 사용자 평가 후 진행한다.

## UX REFORGE · Quick SETUP (사용자 화면 검수 반영)

사용자 스크린샷에서 **복잡한 설정의 시각적 과밀, 주요 행동 버튼이 심화 설정보다 앞에 있는 위치 혼란, 유사한 옵션 분산**을 확인했다. 이 개편은 새로운 기능을 더하기보다는 기존 선택 흐름을 정리한다.

- **빠른 3단계:** 창작 유형(4개) → 메인 장르(필수), 서브 장르(최대 3개, 선택) → 조합 방식(장르/하이브리드/랜덤)과 표현의 구체성(간결/기본/구체적).
- **바로 생성:** 각 단계 아래에 기존의 `이 설정으로 창조하기` 주 버튼과 현재 설정 요약이 함께 배치된다. 심화 설정을 열지 않아도 창작을 시작할 수 있다.
- **점진적 공개:** 서브 장르 검색/전체 목록은 필요할 때만 연다. 선택된 서브 장르는 요약 칩으로 항상 표시되고, 칩에서 즉시 제거할 수 있다. 설정이 접혀도 선택 값은 삭제되지 않는다.
- **고급 설정 한곳에:** 혼돈 레벨, CREATIVE DNA 독창성/선호 분위기, BAN MANAGER와 키워드 품질 통계를 하나의 접힘 패널로 묶었다. 구체성은 빠른 경로에 두고 심화 영역의 중복 선택 UI는 제거했다.
- **자연스러운 진입:** CHAOS의 `취향·밴 편집`에서 SETUP으로 이동하면 고급 설정이 이미 펼쳐진다. 일반 상단 SETUP 탭은 다시 빠른 설정 화면으로 진입한다.
- **데이터와 엔진 유지:** 기존 `creativeDNA`, `genreSelection`, `forgeDocs`, 잠금/결과, 최근 추첨 기록, 내보내기 기능은 삭제하거나 저장 키를 변경하지 않는다. CREATIVE DNA의 밴·취향 가중치 및 SPARK/ECHO/RIFT 엔진은 그대로 작동한다.
- **검증:** 자동 테스트 **150/150 통과**, Vite 프로덕션 빌드 성공. 빠른 생성/심화 설정 접근/서브 장르 선택/재진입/레거시 초안에 대한 6개 신규 UX 회귀 테스트를 포함한다.
- **수동 검수:** 실제 데스크톱·모바일의 첫 화면 밀도, 서브 장르 선택, 키보드 포커스 및 고급 BAN UI는 미리보기 배포 후 사용자 검수를 받는다.

운영 V1은 그대로 두고, 검증된 커밋을 `/preview/v2/` 하위 경로에만 배포한다.

## UX 2.1 — 첫 시작 · 이전 작업 · 잠금 명확화

Work 신규 사용자 감사에서 초기 카드가 이미 생성되어 있는 상태와 저장 복원 상황이 헷갈린다는 피드백을 확인했다. 실제 구현에서 신규 `seedResults`는 **샘플 결과를 생성하지만 잠금은 비어 있다**. 모든 카드가 고정된 사례는 보관된 잠금 상태 또는 사용자 조작에서 비롯될 수 있으므로 '신규 사용자를 자동으로 전부 잠금'으로 잘못 진단하지 않는다.

### 화면 동작

- **첫 방문:** 기존 8~9개 샘플 키워드를 '샘플 미리보기'라고 명시하고 `첫 아이디어 뽑기` / `설정부터 고르기` 행동을 제공한다. 첫 추첨에는 저장할 기존 작업이 없으므로 체크포인트를 만들지 않으며 모든 슬롯이 열린 상태로 추첨된다.
- **기존 초안:** 이전 구조의 `version:1` 초안 및 지금 저장된 활성 초안은 '이전에 작성하던 작업을 자동 복원했어요' 안내가 뜬다. `이전 작업 이어하기`는 값/잠금/FORGE 내용을 변경하지 않는다.
- **명시적인 새 아이디어:** 활성 작업에서 `+ 새 아이디어` → 현재 작업 보관 및 교체 내역 확인 → 승인하는 2단계 과정이다. 이전 작업의 **모든 생성기 결과/잠금, 장르·혼돈, FORGE 원고, CREATIVE DNA, 재추첨 이력** 전체를 독립적인 브라우저 `draft-archives` 키에 기록한 다음에만 현재 생성기의 결과를 재추첨한다. 해당 생성기 FORGE 원고와 잠금만 새로 시작하고 **다른 생성기의 FORGE 원고/결과**는 보존한다.
- **기록 복원:** `보관된 이전 작업`에서 과거 전체 초안을 다시 불러올 수 있다. 기존 활성 작업도 먼저 저장하여 왕복 시 손실되지 않게 한다. 기록을 자동으로 잘라내거나 지우지 않는다.
- **저장 실패 안전장치:** 브라우저 저장소 제한/오류로 이전 작업 기록을 보관하지 못하면 새 아이디어 생성이나 기존 기록 전환을 중단하고 현재 작업 상태를 그대로 둔다. 클라우드 동기화는 제공하지 않는다.
- **잠금 안내:** 카드마다 `🔒 고정 · 유지` 또는 `🔓 열림 · 재추첨`을 표시한다. 잠금 아이콘에 다음 추첨에 어떤 변화가 있는지 설명을 달고, 결과 상단에도 고정/열림 차이를 명시한다. 모든 카드가 잠겼다면 이유와 `전체 잠금 해제하기` 버튼을 함께 보여 준다.
- **기존 API/자료 호환:** 최초 키워드 시드, 현재 `chaosforge.reforge-preview.v2.draft` 버전, 저장된 아이디어, FORGE 종류별 템플릿, 연출, BAN, ECHO/RIFT 등은 유지한다. 새 전체 초안 기록은 `chaosforge.reforge-preview.v2.draft-archives` 별도 키만 추가한다.

### 테스트 및 한계

- 기존 및 신규 회귀 테스트 **161개 전부 통과**; 생성/렌더링 빌드 통과.
- 신규 8개 테스트: 첫 방문 샘플과 초기 잠금, 샘플에서 첫 추첨, 구버전 초안 복원, 전부 잠금 경고, 새 작업 보관/취소/분리, 기록 왕복, 저장 실패 방지, 다른 생성기 FORGE 원고 및 새로고침 복원.
- 샘플은 처음부터 **빈 화면이 아니라 의미 있는 결과 예시**를 보여 주는 방식이다. 이는 첫 방문에 즉시 무엇을 생성하는지 이해시키려는 선택이며, 실제 초보자 사용성 결과에 따라 빈 상태와 비교할 수 있다.
- 브라우저 저장소에만 있는 기록은 브라우저 데이터를 제거하면 복구할 수 없다. 실제 모바일 터치/반응형 수동 검수는 배포 이후 별도 진행한다.

## UX 2.2 — 취향 추천 / 소재 제외 분리, CHAOS 인라인 편집

Work 신규 사용자 감사에서 CREATIVE DNA와 BAN Manager를 한 영역에 두어 **선호 확률 조절과 강제 차단의 차이가 불분명**하고, CHAOS에서 편집하려면 SETUP으로 되돌아가는 점이 주요 불편으로 지적되었다.

### 변경한 흐름

- **SETUP 고급 설정**: 혼돈 레벨과 별개로 (1) `CREATIVE DNA · 취향` 카드 (2) `BAN MANAGER · 제외` 카드로 구성. 취향 카드의 `새로움 1~4`, `분위기`는 가중치 기반 **더 자주 추천하기**, BAN은 **소재·표현 후보 완전 차단 또는 빈도 감소**임을 명시.
- **차단 진입 버튼**: BAN Manager에는 명확한 `차단 목록 관리하기` 버튼과 현재 차단 개수를 표시한다. 열 때만 소재·스타일·문구 등 세부 설정이 나타난다. 설정을 접어도 저장된 값은 그대로 유지된다.
- **CHAOS 내에서 편집**: 설정 요약 바로 옆 `취향 조절` / `차단 관리` 버튼이 있고, 서로 다른 인라인 편집 카드를 여닫는다. 기존 카드·잠금·기획서 내용을 지우거나 SETUP 화면으로 이동하지 않는다. `편집 닫기`로 즉시 결과에 집중할 수 있다.
- **변이 모드 설명**: SPARK(새로운 조합), ECHO(한 가지 계승), RIFT(파격 변형)의 한국어 보조명칭과 선택한 모드가 **이번 추첨에서** 무엇을 하는지 한 줄 설명을 제공한다. 내부 확률 규칙이나 BAN 보호는 변경하지 않는다.
- **좋아요·키워드 도감**: 좋아요 목록을 취향 카드 내부 접힘 영역에 두고, 개별 항목의 좋아요 취소가 가능하다. 도감은 읽기 전용 접힘 영역으로 옮겨 기본 화면의 숫자 과밀을 줄였다.
- **기존 동작 보존**: `creativeDNA` 데이터 구조 및 로컬 저장소 키, 모든 자동 초안/이전 작업 체크포인트, 결과/잠금, FORGE 원고, SPARK/ECHO/RIFT, 완전 차단 우선 규칙, 카드의 좋아요·문구 제외 기능은 그대로 사용한다.

### 검증

- Vitest **168개 전부 통과**(13개 파일) 및 Vite 빌드 성공.
- 신규 UX 2.2 테스트 7개는 취향·차단 패널의 서로 다른 역할, 인라인 전환/닫기, 리로드 복원, 목록 해제, 완전/유연 차단, 관련 없는 잠금·FORGE 원고 불변을 검증한다.
- 텍스트·태그 기반 차단은 의미를 완전히 해석하는 AI가 아니므로 미등록 동의어·은유의 완전 제거는 보장하지 않는다. 사용자가 체감하는 UI 완성도와 실제 터치 동작은 배포 이후 수동 검수가 필요하다.
- 배포 대상은 `/preview/v2/`뿐이며 정식 V1 홈페이지 코드는 변경하지 않는다.

## UX 2.7 — 전체 작업 백업 및 안전 복원

- **LIBRARY → 전체 작업 백업 · 복원:** 현재 화면에 있는 초안을 포함하여 모든 생성기의 결과·잠금, CREATIVE DNA/BAN, FORGE 제목·메모·전체 문서 필드, 최근 추첨 기록, 이전 작업 아카이브, 아이디어 보관함, 사용자 키워드를 **하나의 JSON 파일**로 내보낼 수 있다. 기존 FORGE/CHAOS의 개별 내보내기 메뉴는 그대로 유지한다.
- **로컬 전용:** 계정·클라우드에 업로드하지 않는다. 파일에는 작성 내용·취향 정보가 포함되므로 사용자가 안전한 장소에 보관해야 한다. 다운로드 버튼은 브라우저 다운로드를 *시작*하며 실제 파일 저장 위치를 보증하지 않는다.
- **복원 파일 사전 검사:** `chaos-forge/workspace-backup@1` 포맷과 V2 저장소 scope, JSON, 데이터 구조, ID 중복, 필수 문서/잠금 형식, FNV-1a 무결성 검사, 파일 크기 제한을 검증한다. 무결성 값은 **우발적 손상 확인용**이며 보안 서명이나 암호화가 아니다.
- **조용한 덮어쓰기 방지:** 파일을 선택하는 것만으로 현재 데이터를 변경하지 않는다. 기존/백업의 아이디어·키워드·이전 작업 수를 비교하고, 전체 자료의 **교체 동의 체크박스**를 선택한 후 복원 버튼을 눌러야 한다. 복원 전에 현재 자료를 별도로 백업하고 다른 열린 탭을 닫도록 안내한다.
- **기록 기반 복원:** 초안/아이디어/사용자 키워드/이전 작업의 네 로컬스토리지 컬렉션을 하나의 보호 저널 아래에서 교체한다. 여러 키를 단일 원자 연산으로 저장할 수 없는 로컬스토리지의 한계를 보완하기 위해 이전 원본 데이터를 저널에 남기고 각 저장을 검증한다. 도중에 오류가 나면 이전 원본으로 되돌리고, 브라우저가 중단되면 다음 실행 시 App 초기화 전에 되돌린다.
- **복구 실패 안전장치:** 저널을 되돌리지 못하면 자동 저장과 일반 데이터 쓰기를 막고 사용자에게 경고한다. 저널을 삭제하거나 작업을 초기화해 실패를 감추지 않는다.
- **같은 React 상태로 복원:** 성공 후 현재 생성기·카드·잠금·FORGE 필드·취향·아이디어 목록·아카이브까지 즉시 갱신한다. 사용 중인 V1 저장소 키는 접근하거나 변경하지 않는다.
- **검증:** 기존 테스트 및 신규 백업/복원 테스트를 통해 정상 왕복, 손상·잘못된 버전 파일 차단, 스토리지 오류 롤백, 중단된 복원 재실행, 사용자 명시적 동의와 화면·자료 복원을 검사한다.

### 제한과 후속 과제

- 파일은 브라우저 외부의 **수동 백업**이다. 암호화·클라우드 동기화·다른 기기 자동 전송 기능은 없다.
- 많은 아카이브와 중복되는 보호 저널 때문에 로컬 저장 공간이 부족하면 **복원은 안전하게 중단**될 수 있다. 중요한 자료를 삭제해 강제로 저장하지 않는다.
- 복원은 **선택 파일 내용으로 전체 교체**이지 합치기가 아니다. 사용자 충돌 해결·버전 간 데이터 병합은 추후 별도 기능으로 검토한다.
- 모바일 기기의 파일 선택기, 실제 저용량 저장소, 탭 간 동시 편집을 포함한 실기기 검수는 RC 출시 평가에서 별도 점검한다.
